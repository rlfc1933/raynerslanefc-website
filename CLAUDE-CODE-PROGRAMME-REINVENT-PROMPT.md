# Claude Code Brief — Evolve the Matchday Programme into a "Digital Matchday Experience"

Repo: `rlfc1933/raynerslanefc-website` — **static HTML on Netlify, no build step, vanilla JS + CDN libraries.** You have GitHub + deploy context. This brief **evolves the existing online programme (`programme.html`) into a premium interactive matchday experience** — it does **NOT** rebuild the site or the programme from scratch. Preserve everything that works; enhance section by section.

## READ FIRST — what already exists (preserve all of it)
- **`programme.html`** — the online magazine-style programme fans view. Already has: **cinematic cover with BOTH crests** (`img/badge.png` for RLFC + `#prog-opp-logo` for the opponent), cover colour schemes, chairman message, manager notes, squad grid, double-page sponsor spread, and a **live league table + fixtures rendered from the club's own feed**. Styled with `css/style.css` tokens (`--yellow`, `--green`, `--card2`, fonts `--font-c` etc.), vanilla JS.
- **`programme-print.html`** — the EFL-standard **A4 print edition**. Keep this as the print/PDF output; it is separate from the digital experience.
- **The admin builder** in `admin.html` (programme editor: cover themes, per-page CTAs, opponent crest upload, match sponsors, archive, auto stats/results/scorers, QR). Staff generate the programme here → it must keep working.
- **Data pipeline:** `data/fixtures.json`, `data/squad.json` / `players.json`, `data/sponsors.json`, `data/programme.json` / `programmes.json`, plus the league-table/results feed. The programme reads these — keep the contract.

## HARD RULES (non-negotiable)
1. **Keep it vanilla + CDN. Do NOT introduce React, a bundler, or a build step.** The other AI's repo list is mostly React — use these **vanilla/CDN equivalents instead** so nothing needs compiling:
   - Charts → **Chart.js** (already used elsewhere in the repo) — *not* recharts.
   - Motion → **GSAP** + CSS (respect `prefers-reduced-motion`) — *not* framer-motion.
   - Carousels → **Swiper** (vanilla build). Icons → **Lucide** (vanilla/SVG). QR → a vanilla lib (**qrcode / qr-code-styling**) — *not* qrcode.react.
   - Maps → **Leaflet**. Calendar/reminders → **FullCalendar** vanilla build + `.ics` export (you already have `fixtures-ics.js`). Search → **Fuse.js** (or Orama vanilla).
   - CMS (optional, later) → Decap/Strapi. Analytics → **Plausible/Umami**. Newsletter → **Listmonk**. Forms → **Formbricks**. Load any of these lazily.
2. **Preserve the crest system and branding above all.** RLFC crest `img/badge.png` and opponent crests from `img/crests/` / the admin upload must appear exactly where they do now (cover VS, section headers). Fonts/colours are tokens only — no new fonts, no off-palette colours. It must feel like ONE premium product.
3. **NO FABRICATED DATA — this is critical.** Step 5 has no xG, heatmaps, or win-probability feeds. **Never invent stats.** Every number must come from real club data (`fixtures.json`, `squad.json`, results feed) or the section is **hidden / shows an honest "coming soon"** (blank-if-empty, which the club already does). Do not render fake xG, fake heatmaps, or made-up percentages.
4. **AI features are grounded + labelled.** Any AI text (pre-match hype, opposition preview, tactical note) is generated by a **PIN-gated Netlify function calling Gemini** (reuse the `gen-post.js` pattern / `GEMINI_API_KEY` from the master brief). It must be built **only from real inputs** (our recent results, the opponent's real recent form if available, venue/date) and framed as a preview/opinion — never invented specifics (no fake lineups, no fake injury news). If the key is unset, the section degrades gracefully.
5. **Fast + mobile-first + accessible.** Lazy-load images (consider `sharp` at build-upload time only if a pipeline exists; otherwise pre-sized uploads), lazy-load heavy libs per section, keep Lighthouse green, WCAG AA contrast, keyboard-navigable.
6. Extend the existing `data/*.json` contract; don't break the admin builder or the print edition. Atomic commits, one section per commit. No secrets in the client.

## Build approach
- Work **section by section on `programme.html`** (and its data/admin fields), shipping each as its own commit so nothing breaks mid-way.
- Build a small set of **reusable components** (section header with crest, card, stat tile, QR block, chart wrapper) as vanilla JS + tokened CSS so every section shares one design language.
- Add any new editable content as fields in the **existing admin programme builder** so staff can fill it — never hardcode match-specific content.
- Keep the **A4 print edition** working from the same data (it can stay simpler — print doesn't need the interactive widgets).

## Acceptance criteria
1. `programme.html` is a single, cohesive, on-brand interactive experience across the sections above — desktop/tablet/mobile, fast, accessible — with **RLFC + opponent crests intact** on the cover and section headers.
2. **No React / no build step** was introduced; all libs are vanilla/CDN and lazy-loaded.
3. **No fabricated stats anywhere** — every number traces to real data or the section shows an honest empty state; AI text is grounded + labelled and degrades gracefully without the key.
4. The **admin programme builder and the A4 print edition still work**; the data contract is intact.
5. Each section satisfies at least one goal — inspire, inform, entertain, convert, collect data, reward, promote sponsors, build community, drive donations, or encourage return — and anything that satisfies none is dropped.
